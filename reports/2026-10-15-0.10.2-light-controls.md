`codex/0.10.2-light-controls`. Recompiled, packaged and deployed to the enabled
Scavenger Sense installation. Not pushed/published; no Skyrim session was run.
The previous 0.10.1 ABI correction remains in place. This change updates the
mod's own sensing effects, not global weather/ENB/Community Shaders settings.

## User-facing controls

Look -> Lighting controls is the first group on the Look tab:

- Screen effects: one switch for scene grading and dark vignette together.
- Screen effect strength: 0 preserves the original scene, 1 uses the full
  configured tint/vignette. It multiplies their existing strengths without
  overwriting those settings.
- Keep original brightness: sets brightness and contrast to 1, removes the
  colour cast and disables the vignette. Desaturation and object glow remain
  as configured. Brightness under Screen tint now ranges from 0.2 to 2x.
- Vision -> Object glow: separate switch for sweep and target-lock highlights.
  Glow strength 0 also disables highlights, rather than drawing dark membranes.
  Positive strength changes apply to newly highlighted objects. Names, bars,
  trails and the sonar ring retain their own settings.

Existing personal INIs keep the same appearance: new switches default on and
the new screen multiplier defaults to 1. No personal lighting value was changed
during deployment. Save to INI in the menu after making adjustments.

## Implementation and restoration

New settings round-trip through defaults, loader, range checks, writer and the
English/Chinese menu:

```ini
[Effects]
screenEnabled = true
screenStrength = 1.0
[Vision]
glowEnabled = true
```

ScreenEffectScale/TintBlend feed the native image-space grade, post-process
grade, shader vignette and fallback overlay. Turning the master off or down
to zero releases the native override/restores held values and stops the
plugin's active legacy IMAD. Disabling glow clears only this plugin's shaders,
including the lock highlight, and skips new applications while still producing
tags and NPC data. Engine objects are changed on the existing main-thread task.

The old IMAD is now exclusive with native override/post-process grading;
previously enabling that option could apply multiple grading routes. This is
a code-level correction, not proof of the cause of the user's observed visual
fluctuations. The legacy IMAD takes positive slider edits on the next sweep;
turning the master off stops it during the current sweep. The native and shader
paths read the scale and tint values during updates. Re-enabling object glow
does not recreate highlights that were cleared; subsequent applications use
the new choice. No new shader hooks, engine addresses or dependencies were added.
