# Scavenger Sense 0.10.4 beta — presets/installer audit, 2026-10-15

Based on `b7ed037`; branch `codex/0.10.4-preset-installer`. Updated, rebuilt,
packaged and deployed locally. Not pushed/published. Runtime feature code is
unchanged from 0.10.3 apart from the consistent version bump; this audit fixes
configuration payloads, installer choices, instructions and their verification.

## Findings and corrections

1. The new screen master/glow/actor-smoothing fields were inherited from runtime
   defaults rather than explicitly stored in the shipped presets. All three now
   contain screenEnabled, screenStrength, glowEnabled and smoothingActorsOnly.
   KShakes retains all 257 prior values, including 0.26 s smoothing (261 keys
   now). Each sensing preset retains its original three values and explicitly
   records no HUD hiding and zero smoothing (nine keys now). No tuning was
   imported from the user's current personal file.
2. The two small preset comments incorrectly claimed a partial merge. The actual
   loader starts with RestoreDefaults for every LoadFrom. Comments, README,
   English/Chinese installer guidance and user docs now explain this behaviour,
   the separate installer/personal-INI precedence, and saving after loading.
   Reinstall instructions also distinguish replacing package files from merging:
   old unselected setup fragments can survive a merge. Custom files in the
   package should be backed up before replacement; personal overrides remain
   separate. This was documented without clearing the user's current settings.
3. Simple installer fragments previously duplicated the menu presets. They now
   read the same preset source files. KShakes retains its canonical FOMOD source
   and loadable copy; all 261 values are compared by installer validation.
4. Quick presets skipped detailed pages and did not see the new display guide.
   The existing Controls page now includes two bilingual information entries
   for every route: lighting, actor smoothing, dual equipment, bar PNG/number
   controls, upgrade precedence, fonts and loading presets. No extra page or
   default user preference was added. Quick routes remain four visible pages;
   custom routes remain seven. Non-custom choices explicitly clear the custom
   flag, scoped separately by language.
5. Leave people alone installed no setting while current defaults enable actors.
   It now explicitly sets actor=false. Selecting the chime also previously wrote
   nothing while current defaults disable sound. Both sound answers now write
   true/false, and Silence is recommended to match the actual default behaviour.
6. Full/subtle/vignette-only/no-screen choices now address the new screen master.
   Subtle sets master strength 0.5. No screen effects disables the master while
   retaining the component settings for later adjustment. First-hit combat bars
   now explicitly set combatWhen=struck instead of inheriting fighting mode.
   Sweep-bar descriptions explain their dependency on highlighting people.
7. The shipped README was still labelled 0.6 and described obsolete pages,
   Oathvein/language choices, menu locations and framework font defaults. It is
   replaced with the actual 0.10.4 flow and current requirements, with licence
   notices retained. The font note no longer assumes a fixed framework default;
   it gives explicit configuration and restart steps. The deploy script now
   copies that note as well, without touching the font, OFL or framework INI.

## Verification

- Release x64 build and seven native suites passed: 45 feature checks, 773
  display checks, ABI layout/guard and the three runtime probes remain passing.
- ConfigProbe is a headless adapter around the production Config.cpp loader,
  not a reimplementation of it. It runs only inside isolated temporary Data
  trees. The route checker exercised 102 English/Chinese routes and made 222
  native loads: 102 installer results, 18 named-preset comparisons and 102
  personal-INI precedence checks. Important settings are compared with selected
  fragments; explicit choice contracts catch no-op options. The reported fields
  cover display/lighting, HUD, actors, tracks/gestures, combat and sound; this
  does not test every possible game integration or all rendering.
- Every preset must explicitly contain the new display keys; all quick/custom
  routes must include the new guide. English routes contain no leaked Chinese
   descriptions. File collisions and conflicting routes remain checked. The CI
   configuration now invokes the native probe rather than XML-only simulation;
   the remote workflow itself was not run during this local audit.
- Current translation/ImGui ID checks passed (638 current strings). The 0.10.4
  DLL metadata, 75 framework imports and matching host ImGui layouts passed.
  Framework DLL bytes are unchanged from the 0.10.1 audit.
- Generated FOMOD passed structural and actual ModConfig 5.0 XSD validation.
  It now has 36 payload folders and 68 files: the three added files implement
  explicit full grading, no-people and chime-on choices. ZIP CRC, names and
  every member's bytes match the generated tree. Installed README/presets,
  optional font note and DLL match their packaged counterparts.

No interactive MO2 installation or Skyrim session was performed. These are
native configuration, XML/schema and file checks, not UI/gameplay verification.
Previous startup/gameplay limits and unimplemented regeneration-rate figures
remain as documented in the earlier reports.
