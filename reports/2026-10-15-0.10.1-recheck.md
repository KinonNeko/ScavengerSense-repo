# Scavenger Sense 0.10.1 beta — recheck 2026-10-15

Local development build on `codex/0.10.1-audit`, based on `d0e64b0` (0.10.0).
Built, packaged and deployed locally; not pushed or published. This report
supersedes the framework compatibility assessment in the 0.10.0 report.
The six feedback features are described there; their implementation remains.

## Corrections found during this audit

The updated, enabled Menu Framework DLL still reports 3.14.0, but its bytes
differ from the previously inspected copy. Current SHA256:
`0c107ad4c471c904186b68e1b50b10a66311affb40eb0ba2b8fcca36735d55a2`.
The profile is still J61-BFCO; the winning framework owner is
`SKSE设置菜单-SKSE Menu Framework_new`. Its runtime DLL was not replaced.

Export checks alone were insufficient. The old generated cimgui structs were
configured for non-docking ImGui with obsolete key IO disabled: ImGuiIO 2968
bytes, ImGuiStyle 1104 bytes. The updated host's own layout-check function
requires 14616 and 1140 bytes respectively, despite the same ImGui 1.90.8
version string. This discrepancy is established by static inspection; it does
not establish the cause of a user's unspecified DLL failure or prove a crash.

The plugin now uses official v1.90.8-docking C++ headers, pinned at
`6d948ab47ecf984239af01434f3ed03808dbf188`, through ImGuiCompat.h. Only headers
are used: drawing still goes through the framework's exported C functions,
with no second ImGui implementation/context. cimgui itself was not blindly
updated. A load-time guard checks host version and data layouts before any
callbacks are registered and rejects incompatible hosts with a log entry.
All six layout sizes and the version match this installed framework.

Also corrected an unnecessary per-frame activation-prompt restore/reapply when
HUD suppression is disabled but prompt positioning is enabled. Full unload
restoration still restores both visibility and positioning.

The framework update reset PrimaryFont to Futura Condensed (EN) and disabled
Chinese glyphs. With the user's explicit approval, exactly two settings changed:
`PrimaryFont = MainFont.ttf` and `EnableChinese = true`. The current English
menu language and all other new framework settings remain unchanged. The active
Noto font is already installed. A full Chinese-translation ideograph check
found two existing `矄准` typos; both now read `瞄准`. All 911 distinct CJK
ideographs in the corrected file have glyphs. This is font-data verification,
not an observation of the actual rendered menu or arbitrary modded NPC names.

## Validation

- Release x64 compilation succeeded; CTest 6/6 passed: ABI layout, ABI rejection
  guard, 32 feature checks, and the three production-CommonLib runtime probes.
- PE metadata is 0.10.1.0. All 75 imported framework symbols and HUD registration
  exist. `tools/check_framework_abi.py` compared the compiled header probe with
  constants in the installed host's own version/layout leaf functions.
- Runtime probes: 1.5.97 -> SE, 1.6.1170 -> AE, 1.7.104 -> AE. The 1.7 probe
  exercises the production versionlib filename, format-5 loader and newer VM
  accessor using a synthetic address file, not an actual Skyrim process.
- Translation template: 626 current keys; Chinese covers all of them; 126 old
  entries retained. ImGui widget ID check passed.
- FOMOD structural checks, 102 option routes and actual ModConfig 5.0 XSD passed.
  The tree has 65 files, including the matching ImGui licence. ZIP CRC, member
  names and every member's bytes match that tree.
- The deployed DLL and translation match their packaged counterparts. Personal
  overwrite INI, modlist, plugins, framework DLL and all unrelated existing
  installed assets retain their hashes. The framework INI differs by only the
  two approved lines.

No Skyrim session was started. Actual startup on all runtimes, HUD restoration
with other HUD mods, menu rendering, bar skins, flame appearance and input
gestures remain game-test items. No BodySlide/mesh work is involved.

## Completion and replies

updated CommonLib/runtime handling; bilingual installer; NPC values and
independent player/NPC bar layouts/PNG layers; clearer/custom flame; exposed

skse64.log and ScavengerSense.log if present. Do not attribute it automatically
to the distinct, diagnosed 1.7 runtime classification issue.

posted. Their wording describes an upcoming build and distinguishes offline
validation from gameplay confirmation.
