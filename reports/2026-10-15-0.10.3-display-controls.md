# Scavenger Sense 0.10.3 beta — display controls, 2026-10-15

Based on `4b4e345`, branch `codex/0.10.3-display-controls`. Built, packaged and
deployed locally; not pushed or published. No Skyrim session was run.

## Actor-only stabilisation

Names -> Name tags -> Smooth characters and creatures only defaults ON.
People, animals and other actors use the configured smoothing duration;
non-actor item labels use the projected point directly. Disabling this option
restores the previous all-target smoothing behaviour. Smoothing duration 0
still disables smoothing entirely. The existing feet/head anchoring option
was already actor-only and is independent of this new smoothing scope.

The current personal INI has `smoothing = 0.26` and no new scope key. Its bytes
were preserved; the new default therefore retains 0.26 seconds for actors and
bypasses smoothing for items. Saving the menu writes the new setting:

```ini
[Labels]
smoothingActorsOnly = true
```

Actor identity is resolved from the reference on the main thread before handles
are stripped from render snapshots; animals are included. It is not inferred
from a relationship icon, weapon icon or humanoid race. Bypassing clears that
owner's cached eased point, preventing an old position from returning when scope
is toggled. Tags and combat bars retain separate easing identities. Camera cuts,
long gaps, unknown owners and cache pruning retain their snap behaviour.

## Dual-equipment audit and correction

Found two concrete code issues: the old classifier chose the first recognised
hand (right first), discarding mixed/dual equipment; the enchantment reader then
searched both hands independently, so a left-hand enchantment could colour a
right-hand icon. These are source-level findings, not observed game screenshots.

The new snapshot keeps each hand's type, colour and charge separately. Reading
enchantment data never falls through to the opposite hand. A hand's inventory
entry is used only when it matches that equipped object, with the same hand's
weapon record as fallback. Spells retain their own element/school colour.

Left/right one-handed equipment is drawn left-to-right: mixed and same-type
dual weapons, weapon/spell in either order, dual spells, dual staves, staff with
weapon/spell, shield/weapon and torch/weapon. Shield and torch now have geometry.
Greatsword, battleaxe/warhammer category, bow and crossbow use one icon; empty
hands use a single fists fallback. Vanilla warhammers continue using the existing
two-hand-axe category; this change does not redefine every weapon silhouette.

Name tags, combat chips and player stats share the paired renderer and reserve
the expanded width, so the second glyph does not consume the name/level's space.
Existing custom-marker priority is retained. The existing race-emblem policy
also remains: with race icons on, the corner stats row leaves equipment to the
overhead chip. The current user has weaponIcons, weaponEnchant and raceIcons on.
